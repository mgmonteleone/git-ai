## [Unreleased]

### Added

- **Augment Code (Auggie CLI) preset and hook installer**: First-class support for the Augment Code CLI — both Auggie v1 and v2 (cosmos-agent) — autodetected per-payload from its shape, one preset, no config needed ([#1071](https://github.com/git-ai-project/git-ai/issues/1071), CSS-2302)
  - New `augment` preset (`presets/augment.rs`) — pure parser for Augment's hook payloads (`PreToolUse`/`PostToolUse` for `save-file`, `str-replace-editor`, `remove-files`, `launch-process`, `apply_patch`); `apply_patch` edits — previously dropped by this preset — are now classified as file edits with their patched paths resolved
  - v2 support: `write`/`edit`/`bash` tool attribution, workspace root recovered from the hook process's inherited cwd; session id and model are **never** mined from on-disk session files — no v2 hook payload field reliably links an invocation to a specific session file, and even a sole candidate file in the session directory could be an unrelated leftover or another concurrently active session's file, so v2 always uses the same stable per-workspace hash (`generate_session_id`) for session id and `"unknown"` for model, guaranteeing a checkpoint can never be mis-attributed to the wrong session (CSS-2302)
  - New `AugmentInstaller` (`mdm/agents/augment.rs`) — installs catch-all `[".*"]` matcher entries into `~/.augment/settings.json`, wiring the same config for both v1 and v2; idempotent, preserves user-defined hooks
  - Strict event handling: lifecycle events (`SessionStart`, `SessionEnd`, `Stop`) are explicitly rejected rather than silently misrouted
  - Tool classification: `save-file`/`str-replace-editor`/`remove-files`/`apply_patch` → file edits, `launch-process` → bash (v1); documented read-only tools (`view`, `grep-search`, `codebase-retrieval`, `web-fetch`, `web-search`, MCP tools) are skipped
  - Workspace-relative path resolution: `tool_input.path` is resolved against `workspace_roots[0]`; absolute paths pass through unchanged
- **Telemetry Streams System**: New transcript-based telemetry system for improved session tracking and metrics
  - New `transcripts.db` database for managing AI agent sessions and watermarks
  - Unified `WatermarkStrategy` abstraction supporting multiple tracking methods (byte offset, record index, timestamp, hybrid)
  - Long-lived `TranscriptWorker` in daemon with polling-based modification detection
  - Incremental historical transcript processing for existing sessions
  - Session/trace ID linking in metrics events for server-side correlation and analysis
  - Trailing message capture: messages after last tool call are now recorded in telemetry
  - Support for multiple agent formats: Claude Code, Cursor, Droid, GitHub Copilot
- **Enhanced Metrics Schema**:
  - `session_id` field added to all metrics events (required, unique per agent conversation)
  - `trace_id` field added to checkpoint and commit events (nullable, links related operations)
  - `tool_use_id` field added to checkpoint events (nullable, tracks specific tool invocations)
  - Enables server-side analysis of conversation flows, tool usage patterns, and session lifecycles

### Changed

- **Internal DB Migration**: Existing `internal.db` installations automatically migrate to `transcripts.db` on daemon startup
  - Historical prompt records are converted to session records
  - Watermarks initialized for incremental processing of existing transcripts
  - `internal_db` module retained for backward compatibility but marked deprecated

### Deprecated

- **`internal_db` module**: Now deprecated in favor of `transcripts` module
  - All new installations use `transcripts.db`
  - Existing installations migrate automatically
  - Module retained only for migration purposes

### Fixed

- **Windows daemon startup (`git-ai bg start`/`bg restart`)**: Spawn the detached daemon process directly instead of shelling out through `powershell.exe Start-Process` (CSS-2302)
  - PowerShell's CLR-hosted cold start is far slower and more variable than a native process launch; under CI/scheduler contention this could exhaust the daemon-startup timeout entirely
  - Any failure inside `Start-Process` itself was previously invisible: only the wrapper `powershell.exe` process's own spawn was checked, not whether it actually launched the daemon
  - The daemon child now gets the same `CREATE_BREAKAWAY_FROM_JOB` / `CREATE_NEW_PROCESS_GROUP` / `CREATE_NO_WINDOW` detachment directly, matching the daemon's own self-restart spawn path

### Technical Details

- **Architecture**: Three-component design with transcripts module, TranscriptWorker daemon task, and enhanced metrics schema
- **Processing Model**: 1-second polling interval for transcript modifications, priority queue for checkpoint notifications
- **Watermarking**: Per-agent configurable strategies handle diverse transcript formats (append-only JSONL, SQLite databases, etc.)
- **Migration Safety**: Automatic and idempotent, preserves all historical data

For detailed design rationale and implementation notes, see `docs/superpowers/specs/2026-04-29-telemetry-streams-design.md`.
